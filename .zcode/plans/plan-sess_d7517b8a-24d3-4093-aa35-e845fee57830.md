# План: UI-ядро (U1 + U2 + U4) + U6 доработка

Из `docs/upgrade-2026-07-13.md` UI-дорожка. Скоуп по решению: **вертикальный expandable степпер**. Данные готовы в `task.steps` — почти чистый frontend. U6 endpoint уже существует — минорная типизация.

## Ключевые находки (из исследования)

1. **U6 endpoint уже работает** (`GET /tasks/:id/steps/:stepId/result` + `readStepResult` + `api.getStepResult`). Не нужен как backend-задача — только типизация `StepResult` для frontend.
2. **LiveLog.tsx** — плоские chip'ы, не показывает error/attempts/result_path. Inline-styles (Catppuccin hex), не Tailwind.
3. **Данные всё готовы** в `task.steps` (StepRecord с status/error/attempts/started_at/finished_at/result_path).

## Реализация

### 1. `ui-web/src/shared/ui/StepStatusDot.tsx` — переиспользуемый индикатор

Вынести `STATUS_DOT` из LiveLog в общий компонент (дока: «вынести в переиспользуемый `<StepBadge>`»). Простой dot + опц. пульс для running:
```tsx
export function StepStatusDot({ status }: { status: StepStatus }) { ... }
```
Catppuccin palette (success #a6e3a1, failed #f38ba8, running #89b4fa + pulse, escalated #f9e2af, pending #45475a).

### 2. `ui-web/src/widgets/live-log/StepRow.tsx` — строка степпера (U1 + U2)

Вертикальная строка шага с expand:
```tsx
interface Props { step: StepRecord; taskId: string | null }
```
- **Свёрнуто:** `dot + agent(role) + duration + attempts>1 → "⚠ N попыток"`.
- **Running:** пульс dot.
- **Failed/Escalated:** красная/янтарная рамка + иконка.
- **Expand (клик):** `step.error` (полный текст, не обрезанный) + «Показать вывод шага» → lazy-fetch `api.getStepResult(taskId, step.id)` → output + signals.
- Состояние expand — локальное `useState(false)`.

### 3. `ui-web/src/widgets/live-log/FailureBanner.tsx` — диагностика падения (U2)

Баннер над степпером при `task.steps.some(s => s.status==="failed" || s.status==="escalated_hitl")`:
```
⚠ Упало на шаге codex(review) #2 — budget_exhausted: still calling tools...
```
- Берёт ПЕРВЫЙ failed/escalated шаг, показывает `step.error` (первая строка).
- Для escalated — пояснение «требует ручного разбора, accept недоступен».

### 4. `ui-web/src/widgets/live-log/LogDensityToggle.tsx` — +/- детализация (U4)

Переключатель плотности лога ( Compact / Normal / Verbose ), сохранение в localStorage:
- **Compact:** только stderr-строки + границы шагов (step status changes).
- **Normal:** stderr + ключевые маркеры (VERDICT, error, ✓/✗).
- **Verbose:** весь stdout/stderr (как сейчас).
Фильтрация `stream.lines` по density. Тумблер «только stderr».

### 5. Интеграция в `LiveLog.tsx`

- Заменить плоский `styles.steps` row на `<FailureBanner>` + вертикальный список `<StepRow>`.
- Добавить `<LogDensityToggle>` над логом, фильтровать `stream.lines`.
- Summary «X/Y» в header (через `stepProgress`).

### 6. U6 типизация — `ui-web/src/entities/task/result.ts`

```ts
export interface StepResult {
  envelope_id: string;
  agent: string;
  role: string;
  output: string;
  signals: { name: string; ok: boolean; detail?: string }[];
  success: boolean;
  reason: string | null;
  duration_ms: number;
  timed_out: boolean;
}
```
Обновить `api.getStepResult` return type с `unknown` на `StepResult`. Defensive parse в StepRow (sidecar может отсутствовать/быть битым).
