- `scripts/smoke-units.ts`: добавить тест — 50 параллельных `upsertStep` на одну задачу, после чего все 50 `StepRecord` присутствуют (до фикса терялись). Это детерминированно ловит гонку.
- Commit.

### A2. Regular parallel levels → runBounded (risk #2)
- `src/runner.ts:807-811`: заменить `Promise.all(level.map(runStep...))` на `runBounded(level, concurrency, (step) => runStep(...))`. `concurrency` уже вычисляется на строке 805 — теперь реально используется. `runBounded` сохраняет порядок результатов.
- Проверка: существующий `smoke.ts` + новый тест в `smoke-bounded.ts` (если нужен) — но это поведение уже покрыто. Главное — `tsc` + все smoke green.
- Commit.

### A3. Бюджет ретраев по остатку времени (risk #3)
- `src/workers/types.ts`: добавить опциональное `wallTimeSecOverride?: number` в `WorkerRunOptions`.
- `src/workers/runClaude.ts:35`, `runCodex.ts:42`, `runOllama.ts:65`: таймаут = `opts.wallTimeSecOverride ?? envelope.budget.wall_time_sec` (ollama — `*1000`).
- `src/runner.ts:320-338` (retry loop в `runWorkerOnly`): перед каждым ретраем считать `const left = budgetRemaining(cur, envelope).wall_sec_left;` — если `left <= 0`, не ретраить; иначе передавать свежий `workerOpts` с `wallTimeSecOverride: left`.
- `budgetRemaining` уже импортирован (dead import оживает).
- Commit.

### A4. checkpoint files_changed из git status (risk #4)
- `src/resilience.ts:checkpointFromResult`: добавить параметр `filesChanged?: string[]` (или `cwd?: string` и выполнять `git status --porcelain` внутри). Выберу `filesChanged: string[]` — чище, раннер уже умеет git.
- `src/runner.ts:356` (call site в `runWorkerOnly`, `cwd` в scope): выполнить `git status --porcelain` в `cwd`, распарсить имена, передать в `checkpointFromResult`.
- Тест: `smoke-units.ts` — checkpoint содержит непустой `files_changed` при наличии правок.
- Commit.

### A5. runWithTimeout: kill process group (risk #5)
- `src/workers/spawn.ts:35-40`: добавить `detached: true` в `spawn(...)`.
- `src/workers/spawn.ts:54-59`: `child.kill` → `process.kill(-child.pid, "SIGTERM")` (с guard `child.pid != null` и try/catch на ESRCH); то же для SIGKILL на строке 58.
- `detached: true` безопасен (stdio уже `["ignore","pipe","pipe"]`, tty не наследуется).
- Тест: сложно покрыть юнит-тестом без реального процесса-внука; проверю через `tsc` + существующие smoke (runCodex/runClaude по-прежнему стартуют).
- Commit.

### A6. parseVerdict null → warn (risk #6)
- `src/runner.ts:903`: `level: "info"` → `level: verdict === null ? "warn" : "info"`.
- Тривиальная правка, covered существующим `smoke-loop.ts` (вердикт-логика).
- Commit.

### A7. pathsOverlap: нормализация через path.posix + reject `..` (risk #11)
- `src/workflow.ts:231-234` `norm()`: `import { posix } from "node:path"`; переписать `norm` — backslash→slash, затем `posix.normalize`, затем reject (throw или помечать) если результат содержит `..` или абсолютный. Это закроет `a/b/../c` vs `a/c`.
- Унифицировать с `sanitizePath` в `ollama-tools.ts` — вынести общий helper `sanitizeRelativePath` (или оставить оба, но с единым правилом rejection). Предпочту минимум: починить `norm` в workflow.ts, `sanitizePath` уже использует `relative()` для escape-check — оставлю, но приведу к `posix` для детерминизма.
- Тест: расширить `smoke-workflow.ts` — `pathsOverlap(["a/b/../c.ts"], ["a/c.ts"]) === true`.
- Commit.

### A8. Codex path: устаревший дефолт (находка из E2E-подготовки)
